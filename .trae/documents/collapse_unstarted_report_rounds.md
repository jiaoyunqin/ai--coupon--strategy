# 未开始报告轮次默认折叠实施计划

## Summary

在“促中预算紧张”6 轮报告和“促前券档位设计”7 轮报告中，统一收起尚未开始的 `locked` 章节。

锁定章节只保留紧凑的章节序号、标题和前置依赖状态，不渲染章节说明、空内容占位或章节内操作。用户不能手动展开锁定章节；当现有渐进式流程把章节状态推进为 `queued`、`generating`、`needs-input` 或 `complete` 时，该章节自动恢复完整报告结构。

本次不改变报告生成顺序、对话门禁、队列导航、自定义隐藏、完成进度和业务数据。

## Current State Analysis

项目为单文件静态应用，页面结构、样式、状态和交互均位于：

* `/Users/bytedance/strategy2/index.html`

两套历史报告已有一致的章节状态模型：

* `locked`：尚未开始，等待前序轮次。

* `queued`：已进入生成队列。

* `generating`：正在生成。

* `needs-input`：内容已生成，等待用户确认。

* `complete`：章节完成。

当前问题来自两个文档渲染入口：

* `renderReportDocument()`：渲染“促中预算紧张”6 轮报告。

* `preRenderDocument()`：渲染“促前券档位设计”7 轮报告。

这两个函数目前会为所有未隐藏章节创建完整 `.report-section`。当状态为 `locked` 时，仍然输出章节说明和最小高度为 118px 的 `.report-placeholder`，导致未开始轮次提前占据大量纵向空间。

现有状态推进函数已经会在每次状态变化后重绘整个报告：

* `setReportSectionStatus()` → `renderReportWorkspace()`

* `preSetSectionStatus()` → `preRenderWorkspace()`

因此无需新增独立折叠状态，也无需新增手动展开事件。直接以 `section.status === "locked"` 决定紧凑渲染，即可在状态变为 `queued` 时自动展开。

## Assumptions & Decisions

* 调整同时覆盖“促中预算紧张”和“促前券档位设计”两套渐进式报告。

* “未开始轮次”严格对应现有 `locked` 状态；`queued` 已视为轮次开始。

* 锁定章节保留标题和依赖状态，不完全从报告中移除。

* 锁定章节不可手动展开，进入 `queued` 时由现有状态更新自动展开。

* 锁定章节的正文和空占位不进入 DOM，避免仅靠视觉隐藏造成多余可访问内容和空间占用。

* 用户主动隐藏与系统默认折叠是两种独立行为。

* 本次仅修改 `/Users/bytedance/strategy2/index.html`，不引入框架、依赖或构建配置。
