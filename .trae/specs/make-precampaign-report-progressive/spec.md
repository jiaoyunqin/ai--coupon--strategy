# 促前 HTML 报告渐进式生成 Spec

## Why

当前“促前券档位设计”在分析尚未执行时，就在正式报告画布中展示报告封面、目标约束正文和后续锁定章节，导致“生成队列”和“正式报告”边界模糊，用户会误以为报告已经形成。需要让右侧先承担执行进度，只有真实完成的章节才能进入正式 HTML 报告。

## What Changes

* 保留右侧七步生成队列，继续展示待确认、锁定、排队、分析、写入和完成状态。

* 将正式 HTML 报告改为按已完成章节渐进生成。

* 在分析开始前隐藏正式报告内容，显示轻量“尚未生成报告”空态。

* 只有状态为 `complete` 的章节可以写入正式报告；锁定、排队、分析中、写入中和待确认章节只存在于生成队列。

* 首章完成后才启用“查看报告”和报告自定义能力。

* 全部七章完成后才启用最终 HTML 预览、全屏成品预览和下载。

* 用户修改上游约束后，受影响章节标记为“待更新”，重新分析后在原位置更新，不重复追加章节。

* 本变更只调整“促前券档位设计”历史会话，不修改促中历史会话、促前默认工作台或七步业务顺序。

## Impact

* Affected specs:

  * 促前历史对话七步分析

  * 促前报告生成队列

  * 促前 HTML 报告预览与下载

* Affected code:

  * `/Users/bytedance/strategy2/index.html`

  * `preRenderDocument`

  * `preRenderWorkspace`

  * `preRenderQueue`

  * `preSetReportFocus`

  * `preToggleCustomize`

  * `preBuildStandaloneHTML`

  * 促前章节状态推进与报告工具栏

* Unaffected:

  * 原七步顺序与分析结论

  * 中栏多轮对话

  * “促中预算紧张”报告

  * 新建策略对话推荐卡复刻

  * 促前默认工作台的 01-04 章节编号

## Design Proposal

### 1. 核心原则

右侧区域分为两个职责明确的层级：

| 层级   | 职责      | 可展示内容                           |
| ---- | ------- | ------------------------------- |
| 生成队列 | 表达执行过程  | 全部七步、依赖关系、排队、分析、写入、等待确认、失败和完成状态 |
| 正式报告 | 表达已形成产物 | 报告封面和状态为 `complete` 的章节         |

正式报告不得使用“锁定章节”“待执行章节”或空白占位正文预演未来内容。

### 2. 页面状态

#### 状态 A：尚未执行，0/7

* 默认保持“生成队列”模式。

* 左侧队列展示七步及依赖关系。

* 右侧报告画布不渲染报告封面、章节标题、业务数据或来源卡片。

* 画布只显示轻量空态：

  * 标题：“尚未生成报告”

  * 辅助文案：“确认目标与分析计划后，已完成章节会依次写入这里。”

* “查看报告”“自定义”“全屏”和最终文件入口不可用。

* 不使用大面积骨架屏，不伪装正文已经存在。

#### 状态 B：正在执行，但尚无完成章节

* 当前步骤在生成队列中依次显示“排队中 → 分析中 → 写入中”。

* 右侧画布显示紧凑执行提示，例如“正在分析近 20 天大盘水位，完成后写入报告”。

* 执行提示不使用报告章节样式，不占用正式报告目录。

* 失败或取消时移除执行提示，不保留半成品章节。

#### 状态 C：首章完成，1/7 及以后

* 首次出现 `complete` 章节时挂载正式报告。

* 报告封面此时才出现，并显示“1/7 章节完成”。

* 已完成章节按七步原顺序写入。

* 后续章节完成后原子追加到报告末尾，并使用轻量淡入反馈。

* 页面不自动强制切换到“查看报告”，只在工具栏提示“已写入 1 个新章节”。

* 用户可在“生成队列”和“查看报告”之间自由切换。

#### 状态 D：全部完成，7/7

* 报告状态显示“七章报告已完成”。

* 启用最终 HTML 预览、全屏成品预览和下载。

* 生成待审批策略包，不触发真实预算、发券或发布。

### 3. 首两章写入规则

为避免“确认计划”和“开始分析”语义混淆：

1. 用户确认目标、预算和七步计划后，第 1 章“目标、预算与约束”才变为 `complete` 并写入报告。
2. P0 大盘水位分析完成后，第 2 章“近 20 天大盘水位”写入报告。
3. P1、核销、实验竞对、候选和治理继续按既有门禁逐章生成。

用户尚未确认目标时，第 1 章保持“待确认”，不得进入正式报告。

### 4. 报告正文生成规则

正式报告只包含：

* 报告封面。

* 状态为 `complete` 且未被用户隐藏的章节。

* 当前完成进度和已生成时间。

正式报告不包含：

* `locked` 章节。

* `queued` 章节。

* `generating` 或“写入中”章节。

* `needs-input` 章节。

* “尚未开始”“依赖前序轮次”等队列文案。

* 未来章节的标题、编号或空白容器。

生成中的章节只有在内容、数据口径和来源均准备完成后，才一次性提交到报告正文，避免用户看到逐字段跳动。

### 5. 工具栏门禁

| 控件      | 0 个完成章节 | 1-6 个完成章节      | 7 个完成章节 |
| ------- | ------- | -------------- | ------- |
| 生成队列    | 可用，默认选中 | 可用             | 可用      |
| 查看报告    | 禁用      | 可用             | 可用      |
| 自定义     | 禁用      | 可用，仅列出已完成章节    | 可用      |
| 报告全屏    | 禁用      | 可查看当前草稿        | 可查看成品   |
| HTML 预览 | 隐藏或禁用   | 禁用，并提示“报告尚未完成” | 可用      |
| 下载 HTML | 隐藏或禁用   | 禁用             | 可用      |

禁用控件必须有 `aria-disabled` 和可读原因，不仅依赖灰色视觉。

### 6. 生成队列交互

* 已完成章节可点击，并定位到正式报告中的对应章节。

* 锁定、排队、分析、写入和待确认章节不可定位到正文。

* 点击不可定位的章节时，仅在队列中说明当前依赖，不切换到空报告。

* 当前步骤保持明显但克制的状态反馈，不使用大面积高亮。

* 章节完成后，队列状态先切换为“已完成”，再将章节写入报告。

### 7. 自定义与章节更新

* 自定义面板只列出已经完成并写入报告的章节。

* 未完成章节不出现在隐藏/恢复列表中。

* 用户至少保留一个已完成章节。

* 上游目标、预算或口径改变时：

  * 受影响的已完成章节标记为“待更新”。

  * 报告顶部显示轻量提示“部分章节等待重新计算”。

  * 最终 HTML 下载保持禁用。

  * 重算完成后在原章节位置替换内容，不新增重复章节。

### 8. 视觉与动效

* 空态使用当前蓝色主题、简单图标和两行以内文案，不放置模拟卡片。

* 生成过程只在队列和画布顶部使用紧凑状态条。

* 新章节写入使用 180-240ms 的透明度与轻微位移动效。

* 遵循 `prefers-reduced-motion`，关闭非必要动效。

* 不自动滚动整个页面；仅当用户当前正在查看报告底部时，跟随新章节轻量滚动。

* 窄屏仍由“查看报告”打开右侧抽屉，但 0/7 时仅展示队列与空态。

## ADDED Requirements

### Requirement: 报告未生成空态

系统 SHALL 在促前分析尚无完成章节时隐藏正式报告内容，只展示生成队列和轻量空态。

#### Scenario: 首次进入促前历史会话

* **WHEN** 用户首次打开“促前券档位设计”

* **AND** 尚未确认目标与分析计划

* **THEN** 右侧显示七步生成队列

* **AND** 报告画布显示“尚未生成报告”

* **AND** 不展示报告封面、目标约束正文、来源卡片或锁定章节

#### Scenario: 当前步骤正在分析

* **WHEN** 当前步骤处于排队、分析或写入状态

* **AND** 尚无章节完成

* **THEN** 画布仅显示当前执行提示

* **AND** 不创建半成品报告章节

### Requirement: 已完成章节渐进写入

系统 SHALL 只将状态为 `complete` 的章节按七步顺序写入正式报告。

#### Scenario: 用户确认目标与计划

* **WHEN** 用户确认目标、预算和七步分析计划

* **THEN** 第 1 章变为已完成并写入正式报告

* **AND** 正式报告封面首次出现

* **AND** 进度显示 1/7

#### Scenario: 一个分析章节完成

* **WHEN** 某章节完成数据计算、结论和来源整理

* **THEN** 生成队列先将该章标记为已完成

* **AND** 该章一次性写入报告末尾

* **AND** 未完成章节仍不出现在正式报告中

#### Scenario: 章节生成失败

* **WHEN** 某章节分析或写入失败

* **THEN** 生成队列显示失败与重试入口

* **AND** 正式报告不保留该章的半成品内容

### Requirement: 报告工具门禁

系统 SHALL 根据已完成章节数量控制报告查看、自定义、预览和下载能力。

#### Scenario: 没有完成章节

* **WHEN** 完成章节数为 0

* **THEN** “查看报告”“自定义”和“全屏”不可用

* **AND** HTML 预览和下载不可用

* **AND** 每个不可用控件提供可读原因

#### Scenario: 报告部分完成

* **WHEN** 完成章节数为 1-6

* **THEN** 用户可以查看和全屏当前报告草稿

* **AND** 自定义面板只列出已完成章节

* **AND** 最终 HTML 下载仍不可用

#### Scenario: 报告全部完成

* **WHEN** 七章全部完成

* **THEN** HTML 预览和下载可用

* **AND** 报告状态显示“七章报告已完成”

### Requirement: 已生成章节更新

系统 SHALL 在上游约束变化时标识并原位更新受影响章节。

#### Scenario: 修改预算上限

* **WHEN** 用户修改已确认的预算上限

* **THEN** 受影响章节显示“待更新”

* **AND** 最终 HTML 下载暂时不可用

* **AND** 重新分析完成后原位替换章节内容

* **AND** 报告中不出现重复章节

## MODIFIED Requirements

### Requirement: 七步交互门禁

系统 SHALL 保持目标约束、P0、P1、核销、实验竞对、候选、预算治理的七步顺序。队列状态继续与中栏对话同步，但正式报告只承载已完成章节。

#### Scenario: 推进后续章节

* **WHEN** 用户完成当前章节的确认或追问动作

* **THEN** 下一章节进入排队、分析和写入状态

* **AND** 这些过程状态只显示在生成队列和执行提示中

* **AND** 章节完成后才进入正式报告

### Requirement: 管理促前报告

系统 SHALL 在至少一个章节完成后提供报告查看与自定义，在全部七章完成后提供最终 HTML 预览和下载。

#### Scenario: 查看部分报告

* **WHEN** 至少一个章节已完成

* **THEN** 用户可以切换到“查看报告”

* **AND** 报告只显示当前已完成章节

#### Scenario: 下载最终报告

* **WHEN** 七章全部完成且没有待更新章节

* **THEN** 用户可以预览并下载自包含 HTML 报告

## REMOVED Requirements

### Requirement: 正式报告预展示未执行章节

**Reason**: 未执行章节以锁定卡片、占位正文或预生成封面进入正式报告，会混淆执行计划与最终产物，并造成界面生硬。

**Migration**: 未完成章节只保留在生成队列中；正式报告从首个 `complete` 章节开始挂载，并随章节完成渐进增长。

## Non-Goals

* 不改变促前七步业务顺序和既有分析数据。

* 不重构中栏对话消息和确认动作。

* 不修改“促中预算紧张”报告。

* 不新增飞书文档导出或外部服务。

* 不修改促前默认工作台的 01-04 章节编号。
