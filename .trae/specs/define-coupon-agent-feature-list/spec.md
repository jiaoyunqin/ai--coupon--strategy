# 消费券策略调优 Agent 产品功能清单 Spec

## Why

当前产品已经具备策略对话、促前规划、促中调优及部分基础能力，但缺少一份统一的产品功能地图。需要先明确基础版的一级功能、能力边界和优先级，作为后续信息架构、详细需求和研发排期的共同基线。

## What Changes

- 建立消费券策略调优 Agent 的产品级 Feature List。
- 将产品能力划分为策略决策闭环、任务自动化、能力资产管理、协作与治理四个领域。
- 定义 15 个一级功能及其核心子能力。
- 使用 `P0 / P1` 标记基础闭环与增强能力，避免一次性过度建设。
- 本规格只定义产品能力范围，不包含页面改版、接口设计、数据接入或代码实现。

## Impact

- Affected specs: 产品信息架构、策略分析、任务自动化、分析模版、知识与数据接入、技能与集成、协作治理
- Affected code: 本轮不修改代码；后续可能涉及工作台导航、对话、任务、资源管理及飞书协作模块

## Priority Definition

- `P0`：形成基础产品闭环所必需，覆盖“提出问题 → 获取策略 → 形成产物 → 自动跟进 → 沉淀复用”。
- `P1`：在基础闭环稳定后补充，重点增强活动复盘、模型与工具治理、飞书协作效率。

## 范围确认结论

- Task 1 范围与优先级确认通过：15 个一级功能按策略决策闭环 6 项、任务自动化 2 项、能力资产管理 5 项、协作与治理 2 项分布，覆盖完整且职责可归属。
- `P0` 共 12 项，按目标范围能够串联“提问、策略、产物、自动跟进、资产复用与安全治理”，与首期建立基础产品闭环的目标一致；此处确认的是路线图结构，不代表现状已交付，现有产品的策略对话、促前/促中、历史产物、模版、知识、数据和技能能力仅为该范围提供基础。
- `P1` 共 3 项，排期边界明确：活动复盘后置完整复盘与规则沉淀，首期仅保留入口或上下文兼容；模型与 MCP 后置目录、路由、服务治理和调用监控，不阻塞首期基础选择与调用；飞书协作后置群聊关联、卡片播报和团队配置，首期仅预留任务结果接收与权限契约。现有原型中的相关演示入口不代表提前纳入 P0 验收。

## 现有能力映射

### 状态口径

- **已有基础**：`index.html` 已有可复用的一级页面或核心流程，并具备本地数据和主要交互；仍不代表后端、真实数据、权限、持久化和生产验收完成。
- **待补齐**：已有入口、局部页面或演示交互，但 Feature List 中的关键生命周期尚不完整。
- **未建设**：仅有文案、样例记录、技能名称或禁用入口，尚无该一级功能的可用主流程。

### 缺口与依赖结论

- **重复入口收敛**：独立任务和定时任务目前散落在飞书群详情、对话技能与模版禁用按钮中，后续应分别归口 F07、F08；飞书页面仅保留群级触发与接收视图。活动复盘相关开场、模版和定时样例统一视为 F05 的触发或素材，不作为多个复盘功能。
- **同义功能定界**：“策略灵感”和“内置分析模版”归 F09 的内容浏览/使用入口；知识库与飞书“文档库”分别归 F10 的全局资产、F14 的群级授权范围；技能管理、对话选技能、飞书技能配置分别归 F12 资产目录、F01 运行时选择、F14 群级范围；模型选择留在 F01，模型/MCP 治理归 F13。
- **核心依赖链**：F02 提供活动、波次、目标、预算和策略版本上下文；P0 的 F09-F12 提供模版、知识、数据和技能，P1 的 F13 再增强模型与 MCP 治理；F01、F03-F05 消费这些能力形成 F06 产物；F07/F08 承接异步执行并提供站内结果位置，P1 的 F14 再扩展飞书协作投递；F15 统一提供权限、审计和线上执行边界。
- **首要缺口**：P0 闭环当前断在 F07/F08，且 F09、F11 的产品化不足会阻塞自动任务复用；F05、F13、F14 虽有演示素材或页面，但仍按 P1 边界推进，不以原型可点击作为完整能力验收证据。

## 跨功能产品契约

### 活动与策略上下文契约

| 字段 | 必填规则 | 产品语义 |
| --- | --- | --- |
| 上下文标识 | 始终必填 | 同一活动决策链的稳定标识，跨修订、促前、促中和复盘保持不变。 |
| 上下文版本 | 始终必填 | 一次确认后的不可变快照；任何影响决策输入的修订均生成新版本。 |
| 活动 | 确认前必填 | 稳定活动引用及用户可识别的名称、年份，避免仅靠名称关联。 |
| 阶段 / 波次 | 阶段必填，波次按阶段选填 | 阶段统一为促前、促中、复盘；波次表达当前或目标波次，无波次场景标记“不适用”。 |
| 目标 | 按分析场景必填 | 记录目标指标、目标值、口径和适用范围；多个目标需标明主次或优先级。 |
| 预算 | 按分析场景必填 | 记录币种、预算上限及适用阶段或波次；已分配、已消耗等事实需带对应时点。 |
| 约束 | 无约束时也需明确 | 区分不可突破的硬约束与可权衡的软约束，并标明适用范围。 |
| 策略标识 / 策略版本 | 形成策略后必填 | 策略标识跨修订稳定，策略版本对应一次不可变的策略快照；上下文版本与策略版本分别演进并相互引用。 |
| 父版本 | 修订或派生时必填 | 指向直接来源的上下文版本或策略版本；初始版本为空，不允许形成循环来源。 |
| 状态 | 始终必填 | 上下文至少区分草稿、已确认、历史、已归档；策略至少区分草稿、待确认、待审批、已确认、已归档。 |
| 来源 | 始终必填 | 标明用户新建、对话、模版、历史产物或跨阶段继承，并引用可追溯的来源对象及确切版本。 |

- **创建**：新建时生成稳定上下文标识和初始草稿版本；活动与阶段是确认上下文的最小条件，场景要求的目标、预算或约束未齐时不得伪装为完整上下文。
- **修订**：活动、阶段、波次、目标、预算、约束或策略引用发生变化时生成新版本，保留父版本和修订来源；历史对话、任务和产物继续引用原版本。
- **跨阶段复用**：同一活动进入新阶段时沿用上下文标识并创建新版本，只继承已确认且仍适用的值；波次事实、预算消耗和策略调整不得回写覆盖上一阶段。参考其他活动时新建上下文标识，并通过来源关系关联。
- **缺失值**：统一区分“未知”“待补充”“不适用”，不得以 `0`、空字符串或推测值代替；运行必需值缺失时输出“需处理”并指出补充项，推导值必须标明依据和适用版本。

### 对象创建与引用契约

| 对象 | 单一职责 | 稳定标识与版本 / 快照规则 |
| --- | --- | --- |
| 对话 | 承载用户问题、澄清、分析计划和多轮追问，不充当可复用模版或任务日志。 | 对话标识在续聊中稳定；每次分析固定当时的上下文版本、可选模版版本和能力状态快照。 |
| 分析模版 | 定义可复用的分析目标、步骤和能力依赖，不保存调度、单次运行状态或结果。 | 模版标识跨编辑稳定；已发布版本不可变，编辑、复制或依赖变化形成新版本。 |
| 任务实例 | 承载一次执行的状态、补充输入、尝试记录、日志和结果。 | 每次手动或定时触发生成独立任务标识；进入执行前固定触发来源、上下文、模版及能力版本，重试不改写原始快照。 |
| 定时任务配置 | 定义何时、在何范围、以哪个分析定义运行及投递到哪里，不承载具体执行结果。 | 配置标识跨启停稳定；频率、范围、上下文、模版或接收位置变化形成新配置版本，每次触发保存当时快照。 |
| 报告 / 策略产物 | 报告固化事实、证据和结论，策略产物固化可确认或待审批的决策方案；二者不承担重新执行。 | 同类产物标识跨修订稳定，已生成版本不可变；新结论或方案形成新版本并保留父版本、任务或对话来源。 |

- **标准创建链**：交互分析遵循“上下文版本 → 对话（可选模版版本）→ 任务实例 → 报告 / 策略产物”；无需异步执行的即时回答可留在对话中，但一旦需要留存、复用或自动跟进，应形成明确产物或任务实例。
- **定时创建链**：上下文版本与已发布模版版本 → 定时任务配置版本 → 每次触发的新任务实例 → 报告 / 策略产物；接收人或群仅接收结果引用，不成为产物所有者。
- **引用规则**：跨对象引用同时保留稳定标识和确切版本或运行快照；创建时可推荐最新可用版本，执行前必须向用户明确最终固定版本，历史记录不得随“最新版本”漂移。
- **禁止反向依赖**：上游上下文与能力资产不得依赖对话、任务或产物；模版不得依赖任务结果或定时配置；任务和产物不得回写修改其来源版本。基于历史产物追问时创建新引用和新结果，不改变原产物的来源链。

### 能力可用性契约

知识、数据、技能、模型和 MCP 均按以下五个维度独立判定，再汇总为一个运行结论：

| 判定维度 | 通过或降级条件 | 需处理或阻断条件 |
| --- | --- | --- |
| 生命周期 | 已发布且生效可通过；仍受支持但临近下线可降级运行。 | 草稿、接入中或待同步为需处理；已归档、已撤销或已删除为已阻断。 |
| 管理员启停 | 管理员已启用可继续判定。 | 管理员停用直接已阻断，并提示联系管理员，不得被用户选择覆盖。 |
| 系统健康 | 健康可通过；异常但有已批准的等价回退可降级运行。 | 检查中或短暂同步中为需处理；关键服务不可用且无回退为已阻断。 |
| 当前用户权限 | 所需范围均授权可通过；仅缺可选范围且可裁剪时可降级运行。 | 可申请的必要权限缺失为需处理；策略明确拒绝或超出授权边界为已阻断。 |
| 版本状态 | 已发布且兼容可通过；受支持的旧版本可降级运行并提示升级。 | 未选择必需版本或必须升级为需处理；版本撤销、缺失或不兼容为已阻断。 |

- **结论口径**：`可运行` 表示全部必要检查通过；`降级可运行` 表示核心目标仍可完成且已明确缺失能力、影响和回退；`需处理` 表示完成授权、同步、选择或升级后方可开始；`已阻断` 表示当前请求受治理规则或关键依赖限制不得执行。汇总优先级为“已阻断 > 需处理 > 降级可运行 > 可运行”，必需能力不可用时不得以降级掩盖。
- **资产特有检查**：知识补充来源访问、解析、同步、索引及可引用版本；数据补充连接、凭证、时效、字段与指标口径；技能补充安装、运行依赖、输入完整性及执行范围；模型补充场景路由、额度、上下文能力和安全策略；MCP 补充服务连接、工具发现、工具级授权及操作风险。
- **错误提示**：统一展示资产类型、名称、稳定标识与版本、失败维度、对本次分析的影响、可执行处理动作和责任角色；存在回退时说明差异，权限或凭证错误不得泄露敏感值，也不得只显示笼统的“不可用”。
- **历史状态快照**：任务开始和产物生成时保存各能力的确切版本、五维判定、汇总结论、回退选择和判定时间。历史页面展示“当时状态”，但续聊、复制、重试或定时再运行必须按当前状态重新判定；历史授权快照只用于追溯，不授予当前访问权，停用或归档也不得抹除已有产物的来源记录。

## 路线图验收

### P0 闭环链路与门禁

P0 的最短闭环为：**提问**（F01 + F02）→ **分析**（F03/F04 调用 F09-F12）→ **产出**（F06）→ **跟进**（F07/F08）→ **沉淀**（F06 + F09/F10/F12），F15 对全链路执行权限、安全、审计和线上执行边界控制。F13、F14 为 P1 增强项，不是 P0 闭环的前置条件。

| 门禁 | 通过条件 | 未通过处理 |
| --- | --- | --- |
| G1 提问可分析 | F02 上下文已确认；必需的 F09-F12 依赖通过可用性与权限检查。 | 标记“需处理”或“已阻断”，列出缺失输入、依赖和责任角色，不开始分析。 |
| G2 分析可产出 | 复杂分析计划已经用户确认；结论包含依据、假设、预算与风险，涉及线上变更时仅生成待确认或待审批建议。 | 返回补充输入或调整计划，不生成可执行线上指令。 |
| G3 产出可追溯 | 报告或策略产物具有稳定标识和不可变版本，并在 F06 固化上下文、来源、能力状态及父版本。 | 不得归档、导出或作为后续任务的有效输入。 |
| G4 跟进可闭合 | F07 覆盖一次任务的状态、补充输入、重试、取消、日志和结果；F08 每次触发独立 F07 实例，暂停后不再触发。 | 任务保持失败、待输入或已暂停，并保留原因与审计记录。 |
| G5 沉淀可复用 | 可复用分析沉淀为版本化 F09 定义或经治理的 F10/F12 资产；F06 保留原产物与来源关系，复用前重新校验权限和当前状态。 | 仅保留为历史产物，不进入可复用资产目录。 |

**验收结论**：15 项路线图在规格层支持 P0 完成上述闭环，且不依赖 P1；只有 G1-G5 与 F15 横向治理全部通过，单次链路才算验收通过。按“现有能力映射”，当前产品仍缺 F07/F08 主流程并需补齐 F09/F11，因此该结论不等同于现状交付完成。

| F11 | P0 | 让分析使用可验证、口径明确且健康的数据。 | 数据源管理、分析依赖选择。 | 已测试连接、字段/指标预览、刷新与健康状态、引用关系。 | 外部凭证与网络、F15；由 F01、F03-F05、F09 消费。 |
| F12 | P0 | 以受控、可追溯的方式复用分析和执行技能。 | 技能管理、对话或模版的技能选择。 | 版本化技能、启停/权限状态、调用状态与记录。 | 技能来源与运行条件、F15；由 F01、F07-F09 消费。 |
| F13 | P1 | 统一治理模型和 MCP 工具的选择、范围与运行质量。 | 模型与 MCP 管理。 | 模型目录与路由、MCP 服务/工具配置、连接和调用监控。 | 模型提供方、MCP 服务、F15；运行时由 F01、F07-F09 消费。 |
| F14 | P1 | 在飞书群内协作并接收任务和报告，减少信息搬运。 | 飞书机器人与群级配置。 | 群聊关联、上下文/回复配置、卡片与投递记录、协作配置。 | 飞书授权、F06-F08、F10-F13、F15。 |
| F15 | P0 | 让所有能力在明确权限、口径和线上边界内可审计运行。 | 工作区设置及各功能鉴权、审计控制点。 | 角色与助理规则、长期记忆/指标口径策略、敏感信息策略、审计记录和执行边界。 | 企业身份与组织信息；其余 14 项提供鉴权点和审计事件。 |

矩阵 15 项均具备用户价值、主要入口、核心输出和关键依赖，无缺项；其中 P0 功能不以 F13/F14 为硬依赖，P1 仅增强复盘、模型与工具治理及飞书协作。

## ADDED Requirements

### Requirement: 统一产品功能地图

系统 SHALL 使用上述 15 个一级功能作为产品能力基线，并将所有后续需求归入明确的一级功能，避免出现重复入口、同义模块或职责交叉。

#### Scenario: 评审新增需求

- **WHEN** 产品团队提出新的消费券策略能力
- **THEN** 该需求可映射到一个主要一级功能
- **AND** 如涉及多个功能，应明确主功能、依赖功能与数据流向

### Requirement: 策略全周期闭环

系统 SHALL 覆盖促前规划、促中调优和活动复盘三个业务阶段，并由统一的活动与策略上下文串联对话、分析、任务和产物。

#### Scenario: 用户围绕同一活动持续决策

- **WHEN** 用户从促前规划进入促中调优并在活动后发起复盘
- **THEN** 系统沿用同一活动、目标、预算、波次和已确认策略上下文
- **AND** 不要求用户在不同模块重复录入相同信息

### Requirement: 对话驱动的策略分析

系统 SHALL 允许用户通过新建策略对话描述问题，并组合模版、知识、数据、技能和模型完成多轮分析。

#### Scenario: 发起新的策略分析

- **WHEN** 用户输入策略问题并补充活动上下文
- **THEN** 系统先澄清目标与约束
- **AND** 在需要复杂分析时展示分析计划并等待确认
- **AND** 输出可追问、可追溯、可沉淀的策略结论

### Requirement: 任务与定时任务自动化

系统 SHALL 支持将一次性分析转为独立任务，或将可重复分析转为定时任务，并提供完整的生命周期管理。

#### Scenario: 从分析模版创建定时任务

- **WHEN** 用户选择一个分析模版并点击“创建定时任务”
- **THEN** 系统要求配置执行频率、活动范围、数据上下文和结果接收位置
- **AND** 创建后可查看下次运行时间、启停状态、历史结果和失败原因

### Requirement: 可复用能力资产

系统 SHALL 将分析模版、知识库、数据源和技能作为独立资产管理，并允许它们在对话、任务和定时任务中被组合引用。

#### Scenario: 复用团队分析能力

- **WHEN** 用户选择一个已启用的分析模版
- **THEN** 系统展示该模版依赖的知识、数据源和技能
- **AND** 缺少权限或依赖不可用时在运行前明确提示

### Requirement: 可追溯的策略产物

系统 SHALL 保存历史对话、关键输入、分析过程、数据来源、策略版本和最终产物之间的关联。

#### Scenario: 回看历史策略

- **WHEN** 用户打开一条历史对话或策略报告
- **THEN** 系统展示当时使用的活动上下文、模版、知识、数据、技能和模型
- **AND** 用户可基于该版本继续追问或复制为新策略

### Requirement: 协作与安全治理

系统 SHALL 在飞书协作、能力调用和策略输出过程中执行权限校验、敏感信息保护、操作留痕及线上执行边界控制。

#### Scenario: 策略建议涉及线上变更

- **WHEN** Agent 生成发券、预算、人群或渠道调整建议
- **THEN** 系统将结果标记为待确认或待审批
- **AND** 未经明确授权不得直接修改线上配置
- **AND** 保留操作者、输入、依据、时间和结果记录

## Non-Goals

- 本轮不定义每个功能的完整页面结构和字段级交互。
- P0/P1 均不直接执行线上发券、预算、人群、渠道或其他生产配置；只形成待确认或待审批的建议、快照与交接信息。
- P0/P1 均不自建审批系统；只定义与企业既有审批流程的交接边界。
- P0/P1 均不建设完整企业 IAM；F15 只交付本产品所需的角色、授权、敏感信息保护和审计能力。
- P0/P1 均不建设通用 BI、ETL、数仓或全量指标平台；F11 只负责消费分析所需的数据连接、口径预览和健康治理。
- P0/P1 均不建设公开技能市场；F12 只管理工作区内受控的技能创建、导入、版本、授权和调用。
- P0/P1 均不建设多渠道告警编排或通用告警平台；F08 只提供任务运行失败提示，F14 只在 P1 扩展飞书协作投递。
- 本轮不定义模型选型、算法方案、接口协议或数据库结构，也不把这些技术设计作为任何一级功能的验收条件。
- 本轮不将监控、知识、数据、技能和 MCP 混合为一个不可治理的统一资源入口。
