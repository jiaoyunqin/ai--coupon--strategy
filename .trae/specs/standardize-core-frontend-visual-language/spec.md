# 核心前端视觉语言系统治理 Spec

## Why

当前页面的业务功能、章节主链和交互边界已经基本稳定，但跨促前、促中、历史对话、新建对话和共享侧栏仍存在明显的视觉语言分裂：字号过小、点击目标偏窄、颜色与圆角变体过多、标题层级局部跳级、中英文与 Unicode 符号混用。继续按页面局部补丁演进会放大维护成本，也会削弱业务信息的可读性和操作确定性。

本轮采用“高密度但可读的企业决策台”方向，先治理可读性、标题、符号和共享视觉 token，不改业务布局、数据契约和会话流程。

## 系统审阅结论

### P1：可读性不足

- 当前促中默认工作台有约 382 个可见文本节点低于 12px。
- 当前促前默认工作台有约 290 个可见文本节点低于 12px。
- 页面 CSS 中存在大量 6px、7px、8px、9px 文本规则；候选指标说明、状态标签、时间窗口和辅助说明中均有实际命中。
- H4“采纳后预估效果”当前约 10px，部分业务卡说明仅 7–8px，难以承担信息层级。

### P1：操作目标过小

- 竞对动作按钮存在约 13px 高的实际点击区域。
- 方案标题选择按钮存在约 18px 高的实际点击区域。
- 多个 Tab、证据展开和追问按钮高度集中在 25–30px，视觉与操作反馈不稳定。

### P1：视觉 token 碎片化

- 页面存在大量近似但不相同的白色、灰色、蓝色、绿色和边框色。
- 圆角同时使用 4px、5px、6px、7px、8px、9px、10px、11px、12px、13px、14px、16px、18px、22px、23px 和胶囊值。
- 阴影层级缺乏统一语义，相似卡片分别使用多组近似阴影。
- 同类按钮、状态标签、章节卡和二级卡片在促前、促中、历史对话中表现不完全一致。

### P2：标题和章节语义仍有局部问题

- 促前“AI 券波次策略规划”下直接出现 H4 券组标题，缺少 H3 语义层。
- 促中 `03.1 核心指标监控` 下仍有 H4“当前核心指标监控”，标题语义重复。
- 部分区域仅通过字号和卡片边界表达结构，没有稳定的标题层级。

### P2：符号、术语和标点不统一

- 追问使用字符 `✦`，添加使用 `＋`，关闭使用 `×`，全屏使用 `⛶`，展开使用 `↓`，返回使用 `←`，同时又存在 SVG 图标。
- 侧栏和报告中存在 `AGENT 工作台`、`Knowledge`、`Datasource`、`Skill`、`Pre-campaign queue`、`Report queue` 等非必要英文。
- 标题、元数据和业务组合混用 `·`、`/`、`×`、`｜`、`→`、连字符和不同日期连接号，缺少使用边界。

### P2：窄屏侧栏缺少鼠标提示

- 1280px 以下侧栏收缩至 74px 并隐藏文本标签。
- 图标按钮具备可访问名称，但鼠标悬停时缺少可见 tooltip，非熟练用户难以识别 Knowledge、Datasource、MCP、Skill 等入口。

### 已满足项

- 促前和促中的主章节结构已经明确。
- 促中 03 已使用 `03.1—03.4` 的连续层级。
- 当前浏览器检查无整页横向溢出，既有键盘和 ARIA 主链可用。
- 既有 Axe 专项检查无 critical 或 serious 违规。
- 本轮不需要重做业务信息架构或数据模型。

## What Changes

- 建立核心界面共享的字号、间距、圆角、阴影、文本色、边框色、表面色和控件高度 token。
- 将核心业务正文、指标标签、辅助说明和标题提升到可读的最小字号体系。
- 统一标准按钮、紧凑按钮、图标按钮、Tab、标签和行内动作的最小高度与焦点反馈。
- 修复核心页面标题跳级和重复标题，不改变章节顺序和业务内容。
- 统一追问、返回、添加、关闭、全屏、展开等操作图标，移除核心界面中的混搭 Unicode 图标。
- 中文化非必要英文导航与报告标题；保留 AI、Agent、MCP、GMV、ROI、DAC、UV、Push 等必要业务或技术缩写。
- 统一标题、元数据、维度组合、状态变化和日期范围的标点规则。
- 收敛核心卡片的边框、圆角、阴影和背景层级，减少“卡片套卡片”的视觉噪音。
- 为收缩侧栏补充鼠标 tooltip，并保持可访问名称。
- 基础能力管理页只继承共享字体、控件、图标和导航规则，不进行页面布局重构。
- 历史对话、新建对话和报告工作区只统一共享视觉语言，不改变分析门禁、报告结构和多轮流程。

## Impact

- Affected specs:
  - `rebuild-precampaign-coupon-design`
  - `reorganize-midcampaign-current-next-workflow`
  - `restructure-midcampaign-monitoring-hierarchy`
  - 历史对话与报告工作区
  - 共享侧栏与基础能力入口
- Affected code:
  - `/Users/bytedance/strategy2/index.html`
  - `:root` 设计 token
  - 共享按钮、Tab、标签、卡片、标题、侧栏和对话样式
  - 促前、促中、历史对话、新建对话的少量标题和图标 DOM
- Out of scope:
  - 业务数据、推荐算法、会话状态、上下文隔离和报告门禁
  - 基础能力管理页的独立布局重构
  - 新增第三方字体、图标库、图片或网络依赖

## ADDED Requirements

### Requirement: 统一核心设计 token

系统 SHALL 为全部核心界面提供一套共享的视觉 token，页面组件 SHALL 优先引用 token，不继续新增无语义的局部近似值。

#### Scenario: 字体 token

- **WHEN** 核心界面渲染标题、正文、辅助信息和微型标签
- **THEN** 使用以下语义字号层级：
  - 主章节标题：20px
  - 子章节标题：15–16px
  - 卡片标题：13–14px
  - 正文和主要控件：12px
  - 辅助说明：11px
  - 微型标签：10px
- **AND** 核心业务内容不再使用 6–9px 可见文字
- **AND** 10px 仅用于非关键状态、编号、短标签和不可替代的紧凑元信息

#### Scenario: 间距、圆角和阴影 token

- **WHEN** 核心界面渲染章节、卡片、控件和标签
- **THEN** 间距优先使用 4 / 8 / 12 / 16 / 24 / 32px
- **AND** 圆角收敛为 6 / 8 / 12 / 16px 与胶囊值
- **AND** 阴影只保留低、中、高三个语义层级
- **AND** 状态色与章节装饰色继续分离

### Requirement: 核心文本可读

系统 SHALL 在不降低业务信息完整度的前提下，提高促前、促中、历史对话和新建对话的可读性。

#### Scenario: 默认桌面视图

- **WHEN** 用户在桌面宽屏、1440px、1280px 或 1024px 浏览核心界面
- **THEN** 正文、业务说明、指标标签和表格内容可在默认缩放下直接阅读
- **AND** 不依赖浏览器放大才能识别状态、时间、预算、指标和风险
- **AND** 提升字号后不通过截断重要业务文本来维持原高度

#### Scenario: 760px 窄屏

- **WHEN** 用户在 760px 视口浏览核心界面
- **THEN** 字号不低于桌面同语义层级
- **AND** 允许卡片增高或改为纵向排列
- **AND** 不因压缩字号维持横向布局

### Requirement: 统一操作目标尺寸

系统 SHALL 为核心交互提供稳定的点击和键盘目标。

#### Scenario: 标准与紧凑控件

- **WHEN** 用户操作按钮、Tab、选择器、证据展开或方案选择
- **THEN** 标准控件高度不低于 32px
- **AND** 高频主操作和选择器高度不低于 36px
- **AND** 表格内紧凑行操作的可点击高度不低于 28px
- **AND** 图标按钮的可点击区域不低于 32×32px
- **AND** 当前约 13px 高的竞对动作和约 18px 高的方案标题选择入口被修复

### Requirement: 标题层级连续且不重复

系统 SHALL 使用连续、可解释的标题语义。

#### Scenario: 促前方案章节

- **WHEN** 辅助技术或用户浏览“AI 券波次策略规划”
- **THEN** H2 下存在明确的 H3 工作区标题
- **AND** 券组、波次和配置标题作为 H4 或等价内容标题
- **AND** 不出现 H2 直接跳到 H4

#### Scenario: 促中监控章节

- **WHEN** 用户浏览 `03.1 核心指标监控`
- **THEN** 不再出现语义重复的同名或近同名标题
- **AND** 指标区域内部使用非章节标签或更具体的内容标题

#### Scenario: 动态内容

- **WHEN** 活动、波次、方案、报告章节或会话状态变化
- **THEN** 标题级别、编号和 `aria-labelledby` 关系保持稳定
- **AND** 不因重渲染产生重复 ID 或标题跳级

### Requirement: 统一符号和图标语言

系统 SHALL 使用一致的图标语法表达操作，不依赖不同字体渲染的装饰 Unicode 字符。

#### Scenario: 核心操作图标

- **WHEN** 渲染追问、返回、添加、关闭、全屏、展开或下载操作
- **THEN** 使用同一套 16px 描边 SVG 语法
- **AND** 图标使用 `aria-hidden="true"`，按钮保留清晰可访问名称
- **AND** 追问入口不再直接显示字符 `✦`
- **AND** 返回、关闭、添加、全屏和展开不再混用 `← / × / ＋ / ⛶ / ↓`
- **AND** 业务语义中的 `→`、`×` 和日期连接号不受影响

### Requirement: 统一术语和标点

系统 SHALL 对非必要英文和常用标点建立明确规则。

#### Scenario: 导航与报告文案

- **WHEN** 用户浏览共享侧栏和核心报告工具栏
- **THEN** `AGENT 工作台` 改为“策略工作台”
- **AND** `Knowledge` 改为“知识库”
- **AND** `Datasource / DataSource` 改为“数据源”
- **AND** `Skill` 改为“技能”
- **AND** `Pre-campaign queue` 改为“促前生成队列”
- **AND** `Report queue` 改为“报告生成队列”
- **AND** MCP、AI、Agent、GMV、ROI、DAC、UV、Push 等必要缩写保留

#### Scenario: 标点规则

- **WHEN** 页面展示标题、元数据、日期、维度组合或状态变化
- **THEN** 元数据分隔统一使用 `·`
- **AND** 维度交叉统一使用 `×`
- **AND** 状态变化和前后对比统一使用 `→`
- **AND** 日期范围统一使用 `—`，两侧不加空格
- **AND** 普通并列关系优先使用“、”或“与”，不使用 `/`
- **AND** 业务固定表达如 `3+X / 4+X` 可保留

### Requirement: 收敛卡片和操作层级

系统 SHALL 减少无语义的边框、阴影和同权重操作。

#### Scenario: 章节和卡片

- **WHEN** 用户浏览促前、促中或历史对话
- **THEN** 主章节使用章节边界和轻量章节色
- **AND** 一级内容卡使用边框或低阴影之一，不同时叠加多个强调效果
- **AND** 内部信息组优先使用分隔线、间距或浅底色，不重复套用重卡片
- **AND** 相同层级的卡片使用相同圆角和阴影 token

#### Scenario: 操作优先级

- **WHEN** 同一区域存在多个操作
- **THEN** 每个区域最多一个主操作
- **AND** 次要操作使用次级按钮
- **AND** 追问、展开、查看证据等辅助操作使用低强调样式
- **AND** 不因重复绿色描边按钮抢占业务结论和指标注意力

### Requirement: 收缩侧栏可识别

系统 SHALL 在侧栏隐藏文字时为鼠标和键盘用户提供入口说明。

#### Scenario: 1280px 以下

- **WHEN** 侧栏收缩至图标模式
- **THEN** 工作台、历史对话和基础能力入口显示悬停/聚焦 tooltip
- **AND** tooltip 文案与可访问名称一致
- **AND** tooltip 不遮挡当前操作，不被侧栏裁切
- **AND** 侧栏展开状态和现有导航行为不改变

### Requirement: 历史对话与新建对话继承共享语言

系统 SHALL 让历史对话、新建对话和报告工作区与默认工作台使用同一套字体、控件、图标和术语。

#### Scenario: 对话工作区

- **WHEN** 用户打开新建对话、促前历史对话或促中历史对话
- **THEN** 顶栏、消息、提示标签、输入区和按钮使用共享 token
- **AND** 返回、附件、清空、发送和移动端报告入口使用统一图标与尺寸
- **AND** 多轮分析门禁、报告生成流程和状态不改变

#### Scenario: 报告工作区

- **WHEN** 用户打开生成队列或报告预览
- **THEN** 队列标题、工具栏、章节标题和操作按钮使用统一术语与样式
- **AND** 报告内容、章节状态、自定义、全屏和下载能力不改变

## MODIFIED Requirements

### Requirement: 促前与促中共享视觉系统

促前和促中 SHALL 继续保留各章节的业务强调色，但 SHALL 共享字体、间距、圆角、阴影、控件高度、按钮层级、标题语义和图标规则。章节色仅用于识别章节，不承担成功、警告或失败等业务状态。

### Requirement: 响应式布局

核心界面 SHALL 保持桌面宽屏、1440px、1280px、1024px、860px 和 760px 的既有业务顺序；在窄屏下通过换行、纵向排列和容器内滚动适配，不通过缩小到 10px 以下来维持布局。

### Requirement: 核心界面中文规范

界面 SHALL 优先使用中文表达导航、状态和操作。业务及技术领域已有稳定认知的缩写可保留，但不得在同一层级混用多个等价的中英文名称。

## REMOVED Requirements

### Requirement: 核心业务信息使用 6–9px 字号

**Reason**: 过小字号损害默认缩放下的可读性，且无法稳定承载预算、指标、风险和时间信息。

**Migration**: 按正文、辅助说明和微型标签分别迁移到 12px、11px 和 10px token；通过布局换行和间距调整吸收高度变化。

### Requirement: 核心操作直接使用 Unicode 字符图标

**Reason**: 字符图标在不同字体和平台下字重、基线和尺寸不一致，无法形成稳定的操作语言。

**Migration**: 使用现有页面风格一致的内联描边 SVG；保留按钮可访问名称和原事件绑定。

### Requirement: 核心界面继续新增局部颜色、圆角和阴影值

**Reason**: 无语义局部值导致相似组件表现分裂，增加后续维护和回归成本。

**Migration**: 新增和修改的核心样式必须引用共享 token；既有特殊业务状态值仅在确有语义时保留。
