# 策略 Agent 协作机制与双案例敏捷交互示意 Spec

## Why

当前“促前券档位设计”和“促中预算紧张”已经有完整业务内容，但演示过程更接近预置结果播放，尚未系统表达 Agent 如何理解问题、提出计划、等待确认、分步执行、呈现证据、接受追问并形成券策略结论。现有固定章节 HTML 报告还会迫使所有分析套入同一结构，增加实现和状态同步成本；需要在不改动原版本的前提下，新增按问题动态生成分析卡、由用户选择关键证据、最终收敛为策略结论的敏捷版本，用于同主题对照。

## What Changes

* 梳理 Agent、Plan、Spec、执行和验证阶段的用户交互机制。

* 明确“可见执行轨迹”和“内部思维链”的边界：展示步骤、证据、阶段结论和决策，不逐字展示内部推理。

* 补充会改变分析路径或最终券策略的交互式确认问题。

* 定义计划确认、执行进度、人工门禁和最终交付的统一组件。

* 在两个 `new` 版本中以“对话内分析卡 + 右侧策略结论板”替代固定章节 HTML 报告。

* 定义数据表格、交互式图表、证据固定和按需导出的敏捷呈现规则。

* 保留现有【促前券档位设计】【促中预算紧张】历史对话及全部交互，不用新设计覆盖旧版本。

* 新增【促前券档位设计new】【促中预算紧张new】两条独立历史对话，专门承载敏捷协作版本。

* 为【促前券档位设计new】设计固定 7 步协作脚本。

* 为【促中预算紧张new】设计固定 6 步协作脚本。

* 定义自动演示与用户手动接管的衔接方式。

* 本轮仅产出设计方案，不修改 `index.html` 或任何产品代码。

  * 新版促前保留 7 步、新版促中保留 6 步的业务顺序

## 设计目标

### 1. 用户感知

用户应始终能够回答五个问题：

1. Agent 当前理解的任务是什么。
2. Agent 准备按什么步骤处理。
3. 当前执行到哪一步，使用了哪些数据。
4. 哪些结论已确定，哪些仍是假设或待补充。
5. 用户下一步可以确认、调整、追问或导出什么。

### 2. 设计原则

* **先计划，后展开**：复杂任务先给出紧凑计划卡，不直接倾倒最终结论。

* **结论优先，证据下钻**：每一步先显示结论与影响，技术口径、长表和来源按需展开。

* **少问但问关键问题**：只有缺失信息会改变分析路径、成本或最终决策时才中断提问。

* **缺数可继续**：非阻断信息标记为“待补充”，先使用参数化规则或显式假设推进。

* **阶段可接管**：用户可在每个关键门禁点确认、调整、追问或暂停自动演示。

* **结论驱动**：先回答“券策略应该怎么定”，表格和图表只作为支撑结论的过程证据。

* **分析卡按需生成**：每次只生成当前问题所需的表或图，切换维度时更新原卡，不预建固定章节。

* **证据由用户选择**：只有被用户固定或被最终结论引用的分析卡进入右侧策略结论板。

* **业务状态明确**：最终方案使用“候选”“待确认”“待审批”等状态，不伪装为已执行。

* **界面文案克制**：不在界面展示 Mock、真实数据、Revision、内部 ID 或原始工具日志。

## Agent 用户交互机制

### 1. 模式分工

| 阶段       | 目的              | 用户可见内容                              | 用户动作       | 退出条件      |
| -------- | --------------- | ----------------------------------- | ---------- | --------- |
| 普通 Agent | 直接处理范围清晰、风险低的任务 | 简短理解、执行更新、结果                        | 补充、追问、停止   | 结果交付      |
| Plan     | 在执行前统一目标、范围和步骤  | 目标、假设、步骤、依赖、验证方式                    | 确认、调整、补充约束 | 计划获确认     |
| Spec     | 将复杂变更固化为可验收契约   | `spec.md`、`tasks.md`、`checklist.md` | 审阅、修改、批准   | 规格获批准     |
| 执行       | 按已确认计划完成工作      | 当前步骤、状态、关键证据、阶段结果                   | 暂停、纠偏、处理门禁 | 任务完成      |
| 验证       | 用测试或清单核对结果      | 通过项、失败项、残余风险                        | 接受或要求修复    | 全部通过或明确阻断 |

Plan 与 Spec 并非每次都连续出现：

* 范围较小、实现方式明确时，可以直接使用 Plan。

* 涉及多阶段流程、数据契约、跨模块行为或长期维护时，使用 Spec。

* 信息不足时先提出交互式问题；信息足够时直接给出计划或规格，避免为了互动而互动。

### 2. 交互式问题

问题卡仅在以下情况出现：

* 缺失答案会改变分析路径或最终建议。

* 存在两个以上都合理但业务取舍不同的方案。

* 即将发生外部、不可逆或高风险动作。

* 用户要求与已有约束冲突。

问题卡结构：

| 区域  | 内容                  |
| --- | ------------------- |
| 问题  | 一句话说明需要用户决定什么       |
| 原因  | 说明该选择会影响哪一步或哪项产物    |
| 选项  | 2-4 个互斥或可多选选项，附简短影响 |
| 自定义 | 允许输入未覆盖的答案          |
| 推荐  | 必要时标记建议选项并说明依据      |

非阻断缺失项不弹窗，放入计划卡的“待补充”区，并提供“现在补充”入口。

每个案例最多设置 4 个阻断式确认点，避免把分析拆成问卷：

| 确认点  | 需要用户确认什么                 | 为什么必须确认              | 结果如何影响后续        |
| ---- | ------------------------ | -------------------- | --------------- |
| 目标门禁 | 第一优先目标和不可突破的底线          | 决定指标排序和候选淘汰规则       | 改变结论权重与候选范围    |
| 假设门禁 | 缺数时按假设继续、只给方向性结论或等待补数   | 防止把假设伪装成确定事实         | 决定是否测算精确数值      |
| 路径门禁 | 下一步优先验证哪类不确定性            | 避免一次生成所有图表           | 决定下一张动态分析卡      |
| 决策门禁 | 采用哪个候选作为基准，是否形成待审批策略结论  | 最终策略必须由业务确认          | 决定结论板和最终策略快照   |

同一确认点尽量使用单选、双选或带推荐项的快捷选项；只有数值、权重和特殊约束使用自由输入。

### 3. 计划确认

计划卡保持首屏可扫描，不展示长篇说明，默认包含：

* 任务目标。

* 当前上下文和已加载数据。

* 关键约束与待补充项。

* 计划步骤及预计产物。

* 需要用户确认的门禁。

计划卡末尾直接承接第一个目标门禁。主操作固定为“确认目标并开始”，次操作为“调整计划”，辅助操作为“补充约束”。详细口径放在展开区。

### 4. 执行过程

执行中不逐字展示内部思维链，也不向用户倾倒命令、临时假设和原始日志。对话区展示的是可核验执行轨迹：

| 字段   | 用户可见含义                |
| ---- | --------------------- |
| 当前步骤 | 正在完成计划中的哪一步           |
| 状态   | 排队、分析中、生成中、等待确认、完成、失败 |
| 动作摘要 | 正在读取、比较、计算或生成什么       |
| 使用证据 | 数据范围、筛选条件、来源类型        |
| 阶段结果 | 已得到的结论、异常或缺口          |
| 下一步  | 自动继续，或等待用户执行某个动作      |

执行更新采用单条可更新进度卡，阶段完成后折叠为一行摘要，避免每个内部动作都生成新消息。

### 5. 人工门禁

默认只在以下节点阻断自动推进：

1. 目标和分析计划确认。
2. 缺失关键参数时的假设确认。
3. 下一验证路径或候选方向确认。
4. 最终候选、审批或外部动作确认。

数据读取、指标计算、分析卡生成和导出文件排版无需逐项确认。用户仍可随时暂停或追问。

### 6. 验证与收尾

结束消息只保留：

* 最终结论或完成内容。

* 关键产物入口。

* 已完成验证。

* 尚未解决的限制或待审批事项。

原始执行日志、内部工具输出和重复过程说明不进入最终消息。

## 敏捷产物呈现机制

### 1. 三层承接结构

| 层级   | 作用             | 呈现位置          | 内容                              |
| ---- | -------------- | ------------- | ------------------------------- |
| 对话层  | 推进当前问题和用户确认    | 中栏对话          | 结论摘要、确认问题、执行状态                  |
| 分析卡层 | 承接当前步骤所需的数据分析  | 对话内，可展开或全屏   | 指标、表格、交互式图表、计算和假设               |
| 结论层  | 持续收敛最终券策略      | 右侧策略结论板       | 当前策略结论、已确认约束、固定证据、风险和待决事项       |

HTML 报告不再是过程中的必选容器。只有用户完成最终确认并明确选择“导出策略快照”时，才将结论板中的内容按当前状态组装为一次性文件；文件不反向控制对话和分析状态。

### 2. 动态分析卡

分析卡是表格和图表的统一容器，按当前问题即时生成，不预设章节。每张卡包含：

| 区域    | 内容                            |
| ----- | ----------------------------- |
| 问题    | 这张卡正在回答什么业务问题                 |
| 一句话结论 | 先给出对券策略的影响                    |
| 主体    | 指标、表格、图表或计算结果                  |
| 口径    | 时间范围、筛选条件、单位和必要假设              |
| 操作    | 切换维度、追问、固定为证据、替换、移除            |

卡片状态：

* **临时**：默认状态，只服务当前对话，不进入结论板。

* **已固定**：用户点击“固定为证据”后进入右侧结论板。

* **已替换**：切换同一问题的维度或口径后更新原卡，保留简短变更记录，不新增重复卡。

* **已引用**：最终策略结论直接使用该证据，自动固定且不可静默删除。

* **已排除**：用户判定口径不适用，保留排除原因但不参与最终结论。

### 3. 数据表格

* 6 个以内核心指标优先使用指标卡。

* 10 行以内、列数可控的比较直接在分析卡内展示。

* 长表默认显示摘要、关键行和前若干行，完整数据在同一分析卡内按需展开。

* 表头固定标明单位、时间范围和比较口径。

* 差异列同时显示绝对差和必要的相对差，不只依赖颜色。

* 关键行允许“追问”“固定为证据”“加入候选”。

* 需要复用时提供表格文件；只用于解释当前结论时不制造额外下载入口。

### 4. 可视化图表

| 数据问题 | 首选图形          | 交互                   |
| ---- | ------------- | -------------------- |
| 时间趋势 | 折线图           | 指标切换、时间点提示、异常标记      |
| 方案对比 | 分组条形图或斜率图     | 方案高亮、统一口径切换          |
| 贡献拆分 | 瀑布图或贡献条       | 展开计算口径               |
| 人群规模 | 横向比例条         | 显示绝对规模与覆盖缺口          |
| 漏斗转化 | 漏斗图配明细表       | 点击阶段下钻人群、渠道、券档       |
| 波次预算 | 深色高对比度表格配堆叠条  | 切换基准、缩减和峰值情景         |

图表必须同时提供一句话结论和可读数据摘要。默认只渲染一张回答当前问题的主图；用户切换指标、维度或情景时原位更新。点击“展开分析”后在独立面板查看明细，关闭后回到原对话位置。

### 5. 右侧策略结论板

右侧区域不再按固定章节展示 HTML 报告，而是维护一个轻量、动态的策略结论板：

| 区块     | 行为                                             |
| ------ | ---------------------------------------------- |
| 当前策略结论 | 始终置顶，随已确认信息更新；未确认时明确标记“暂定”                   |
| 已确认约束  | 只记录用户已确认的目标、预算、ROI、覆盖和治理边界                  |
| 候选策略   | 最多展示 3 个，保留当前基准和淘汰原因                         |
| 关键证据   | 只收纳已固定或被结论引用的分析卡，建议不超过 5 张                    |
| 风险与待决  | 展示缺数、假设、风险和下一次需要用户确认的问题                      |

结论板不显示步骤队列、空章节或所有中间分析。用户可以取消固定未被结论引用的证据，也可以从结论板重新打开原分析卡。

### 6. 最终策略快照

最终交付以“策略快照”而非固定 HTML 报告为主，内容固定为：

1. 一句话策略结论。
2. 采用的券档、人群、渠道、节奏和预算规则。
3. 关键约束与适用条件。
4. 3-5 个核心证据摘要。
5. 风险、待补数据和止损条件。
6. 当前状态与下一业务动作。

策略快照可直接保留在对话和结论板中。用户明确需要分享或归档时，再按当前快照导出 HTML、表格或图片；导出是末端动作，不要求预先维护固定报告结构。

### 7. 表格与图表交付路由

参考 Aime 的产物策略，新版历史会话根据结果规模和交互需求选择最轻的承接形式：

| 结果特征 | 首版交付形式 | 对话内呈现 | 补充能力 |
| ---- | ------ | ------ | ---- |
| 不超过 6 个关键指标 | 指标摘要卡 | 全量展示 | 追问、固定为证据 |
| 不超过 10 行且列数可控 | 内联表格 | 全量展示 | 排序、追问、固定为证据 |
| 超过 10 行或需要复用 | 摘要 + 下载文件 | 显示结论、关键行和数据口径 | 下载 CSV；结构化结果可下载 JSON |
| 中间分析数据需要复查 | 步骤产物文件 | 显示文件名、所属步骤和生成状态 | 下载、重新生成、从结论板定位 |
| 简单趋势或方案对比 | 内联静态图 | 展示主图和一句话结论 | 悬浮提示、展开查看数据 |
| 需要筛选、联动或多维切换 | 交互式分析面板 | 对话显示缩略图和“打开交互分析” | 筛选、联动、悬浮提示、恢复默认 |

首版以浏览器本地能力实现：

* 表格大结果优先提供 CSV，结构化快照提供 JSON；不为 Excel 新增重型依赖。

* 简单图表使用页面内 HTML/SVG 展示，不生成无交互价值的独立网页。

* 交互图表在工作台内打开可访问的分析面板，不依赖外部托管链接。

* 飞书文档嵌入作为后续协作扩展，本轮不连接真实飞书文档接口。

* 产物链接只指向当前会话生成的本地文件或页面内分析面板，离开或重置会话时正确释放临时资源。

### 8. 中间产物

每次生成的大结果或重要中间数据进入“本次分析产物”列表，记录：

* 产物名称。

* 所属分析步骤。

* 数据口径和筛选条件。

* 文件类型与生成状态。

* 生成时间。

* 下载或重新生成入口。

中间产物默认不进入最终策略结论板。只有用户固定、最终结论引用或最终导出需要时才成为关键证据。

### 9. 最终回复契约

两个新版案例的最终回复固定包含以下五部分，且顺序不变：

1. **核心结论**：一句话说明最终券策略及适用条件。
2. **执行状态**：说明已完成、待确认或待审批，不暗示已经线上执行。
3. **数据口径**：列出时间范围、比较对象、关键假设和缺数边界。
4. **已生成产物**：列出策略快照、表格文件、图表或交互分析入口；没有产物时不显示空区块。
5. **待补事项**：列出仍缺少的数据、业务确认、风险或下一步动作。

### 10. 来源与边界

用户界面统一使用以下业务状态：

* 已加载。

* 由当前数据计算。

* 用户补充。

* 待补充。

* 待确认。

* 待审批。

不展示内部数据 ID、工具名称、技术版本或“Mock/真实数据”标签。若需要说明演示边界，使用面向业务的文案，例如“当前为案例数据快照，不会提交线上配置”。

## 工作台结构

### 1. 桌面布局

* 左栏：工作台入口、历史对话和当前案例选中状态。

* 中栏：用户消息、计划卡、确认问题、执行进度、动态分析卡、追问与输入框。

* 右栏：策略结论、已确认约束、候选、固定证据和风险待决。

### 2. 响应式

* 宽屏：三栏同时展示。

* 中等桌面：左栏收起，保留中栏与右栏。

* 窄桌面或移动端：对话为主，结论板通过“查看结论”抽屉进入；每步核心结论和分析卡仍在对话内可见。

* 任一视口都不因长表格或图表产生页面级横向滚动。

## 历史对话版本策略

### 1. 导航与标题

历史对话列表按同主题相邻方式展示：

1. 【促前券档位设计】
2. 【促前券档位设计new】
3. 【促中预算紧张】
4. 【促中预算紧张new】

标题必须逐字使用以上文案，不额外增加“旧版”“新版”“实验版”等界面标签。用户通过名称中的 `new` 区分版本。

### 2. 版本职责

| 历史对话 | 职责 | 变更边界 |
| ---- | -- | ---- |
| 【促前券档位设计】 | 保留当前固定报告和既有 7 步应答体验，作为原版本对照 | 不修改 DOM、数据、状态、计时和交互 |
| 【促前券档位设计new】 | 承载促前敏捷分析卡、交互确认和策略结论板 | 使用独立状态与渲染入口 |
| 【促中预算紧张】 | 保留当前固定报告和既有 6 步应答体验，作为原版本对照 | 不修改 DOM、数据、状态、计时和交互 |
| 【促中预算紧张new】 | 承载促中敏捷分析卡、交互确认和策略结论板 | 使用独立状态与渲染入口 |

### 3. 状态隔离

* 四条历史对话均有独立选中态和进入路由。

* 两条 `new` 会话分别维护独立的消息、确认答案、执行步骤、分析卡、固定证据、结论板、产物文件和临时资源。

* 打开或重置 `new` 会话不得清空、推进或改写对应原版本。

* 在原版本和 `new` 版本之间切换时，各自当前进度保持不变。

* `new` 会话提供“重新演示”，仅重置当前 `new` 会话，并释放该会话生成的临时下载链接。

* 现有新建策略对话中的两个推荐卡片及其旧版复刻路由保持不变；新版仅从新增历史对话入口进入，避免比较口径混淆。

## 新版双案例共用演示机制

### 1. 启动

用户点击【促前券档位设计new】或【促中预算紧张new】后：

1. 对应历史项进入选中态。
2. 主区域进入对应 `new` 案例工作台。
3. 首次进入时以历史用户消息展示原问题。
4. Agent 展示任务理解、数据状态、分析计划和第一个确认问题。
5. 不直接跳到最终结论或生成全量图表。

### 2. 自动演示与手动接管

* 默认进入自动演示，可按预置选择依次展示完整协作过程。

* 自动演示中的用户确认必须以可见的问题卡和用户选择呈现，不能悄悄跳过门禁。

* 顶部提供“暂停演示”；暂停后当前步骤和产物状态保持不变。

* 用户点击任一追问、调整或输入框时，自动演示暂停并转为手动接管。

* 提供“继续演示”和“重新开始”，重新开始必须彻底重置状态。

* 自动演示只模拟本地分析与产物生成，不显示线上动作已完成。

### 3. 对话节奏

* 开场理解与计划：一次完整回复。

* 执行进度：每步使用同一张状态卡更新，完成后折叠。

* 阶段结论：每步一条主体回复，按用户选择最多生成一个主图或一个主表。

* 用户动作：每步保留一个主操作、一个次操作和追问入口。

* 最终交付：策略快照加按需导出入口，不重复粘贴全部过程数据。

## Case A：【促前券档位设计new】

### 1. 开场问题

> 请结合历史复盘、近期大盘水位、类目需求、实验钱效和竞对变化，设计 3+X / 4+X 券档、人群、渠道、发放节奏与预算方案。

开场回复先重述目标，展示已加载数据、待补充项和 7 步计划，并直接询问第一优先目标和钱效底线。7 步是业务推进顺序，不对应固定报告章节。

### 2. 促前确认问题

| 时机    | 交互式问题                     | 快捷选项                                                   | 默认演示选择                                |
| ----- | ------------------------- | ------------------------------------------------------ | ------------------------------------- |
| 开始前   | 本次券策略第一优先保障什么？            | `增量 GMV`、`ROI`、`覆盖规模`、`自定义权重`；同时填写预算和底线            | 增量 GMV 优先，ROI 不低于 6.2，预算上限 1.28 亿 |
| 大盘水位后 | 本期库存和正式预算尚未加载，如何继续？       | `按历史样本与当前上限测算`、`仅给方向性结论`、`等待补数`                    | 按历史样本与当前上限测算                        |
| 进入证据分析 | 下一步优先验证哪两类不确定性？           | `类目机会`、`领取核销`、`实验钱效`、`竞对压力`，最多选择两项                 | 类目机会 + 领取核销                           |
| 候选形成后 | 采用哪一方案作为基准？               | `3+X 钱效优先`、`4+X 均衡增长`、`4+X 峰值增长`、`继续调整`                | 4+X 均衡增长                                |

### 3. 七步交互示意

| 步骤                      | Agent 可见动作                                       | 按需分析卡                       | 用户交互                       | 策略结论板变化            |
| ----------------------- | ------------------------------------------------ | --------------------------- | -------------------------- | ------------------ |
| 1. 确认目标、预算与治理约束         | 将目标拆为增量 GMV、预算上限、ROI/CAC/人均补贴底线和治理边界             | 目标与约束卡                     | 回答目标门禁，或补充输入              | 写入已确认约束，结论保持暂定     |
| 2. 评估活动前 20 天大盘水位       | 读取 GMV、DAC、客单和订单趋势，先给“增长主要由 DAC 驱动”的结论          | 4 指标卡；用户展开时生成趋势图或贡献条       | 选择缺数处理方式、追问或固定证据         | 更新当前判断，可固定大盘证据     |
| 3. 识别类目需求爆发与优先级         | 根据路径门禁，仅生成用户优先关注的类目分析                         | 类目机会表或需求放大图                 | 查看二级类目、调整优先级、固定证据        | 更新重点类目和适用券档        |
| 4. 复盘领取核销链路             | 按用户选择的券档、人群或渠道解释主要瓶颈                         | 核销漏斗或深色对比表，原位切换维度          | 切换维度、交叉下钻、固定证据            | 更新券档和人群限制          |
| 5. 合并实验钱效与竞对压力          | 当该路径被选择或候选需要验证时才生成对应卡片                      | 实验比较表或竞对信号卡                 | 查看显著性、追问是否跟进竞对            | 补充候选的证据或风险         |
| 6. 生成 3+X / 4+X 候选并测算预算 | 同口径比较钱效优先、均衡增长、峰值增长三案                       | 三候选决策卡；按需展开统一比较表            | 选择基准、调整预算、替换候选             | 写入当前基准和淘汰原因        |
| 7. 完成波次预算、治理与策略包        | 只围绕已选基准展示波次、情景和治理条件                         | 深色波次预算表、情景卡、治理清单            | 确认候选、补充治理项、生成策略快照         | 固化最终结论、风险和待审批状态    |

### 4. 关键对话文案示意

#### 计划确认

Agent：

> 我会先确认增长目标和钱效底线，再依次核对大盘水位、类目机会、历史核销和实验钱效，最后比较 3+X / 4+X 候选。正式预算批复和实时库存尚未加载，不阻断方案测算，但会作为上线前门禁。

用户默认演示动作：

> 确认目标与计划，ROI 不低于 6.2，预算上限 1.28 亿。

#### 候选选择

Agent：

> 三案均满足当前 ROI 下限。方案二在 1.15 亿申请预算下，兼顾 6.60 亿增量 GMV 与 6.52 ROI，规模和预算弹性最均衡；高门槛券仍需限制泛发。

用户默认演示动作：

> 采用方案二为基准，并测算预算缩减 10% 的调整方式。

#### 最终交付

Agent：

> 已形成 4+X 均衡增长候选、波次预算和风险护栏。该方案当前为待审批策略包，正式预算、库存和参与角色确认完成前不会进入执行。

最终产物：

* 促前券档位设计策略快照。

* 方案二配置摘要与已确认约束。

* 3-5 张关键证据卡。

* 波次预算、风险与治理清单。

* 按需导出的待审批策略包。

> 最后一波次预算紧张，需要降低 X 覆盖比例；应优先发大盘 L4-L5，还是 jp/t8 重点人群？

| ----- | ------------------------- | ------------------------------------------------- | ------------------------- |

| 计划确认  | 精确预算和 X 单人成本缺失，如何继续？     | `先按参数化规则分析`、`输入可覆盖人数/比例`、`仅比较现有 V1/V15`         | 先按参数化规则分析                |

### 3. 六步交互示意

| 2. 对比总体表现           | 比较 GMV、补贴、兑换比和支付费率，明确 6.32 与 6.24 基本持平    | 4 指标对比表；按需切换斜率图          | 选择下一验证路径、追问差异           | 更新“不能直接判定胜负”       |

### 4. 关键对话文案示意

#### 计划确认

Agent：

> 当前可以比较 V1/V15 的累计两天表现和人群规模，但精确预算、X 单人成本与剩余库存仍待补充。我可以先按参数化规则判断，再在你补充预算容量后更新覆盖方案。

用户默认演示动作：

> 先按参数化规则继续，重点拆分效率和人群规模影响。

用户默认演示动作：

#### 最终交付

Agent：

> 当前数据无法无条件证明 V1 或 V15 胜出。建议在大盘 L1-L5 中由算法按预期增量选择部分人群；若业务必须保障重点人群触达，则设置 jp/t8 保底层，再分配剩余预算。候选需补充显著性和精确成本后进入审批。

最终产物：

* 促中预算紧张策略快照。

* 3-5 张关键证据卡。

## ADDED Requirements

### Requirement: 新增两条独立历史对话

系统 SHALL 在历史对话列表新增【促前券档位设计new】和【促中预算紧张new】，并保留两个原版本不变。

#### Scenario: 查看历史对话列表

* **WHEN** 用户打开历史对话列表

* **THEN** 【促前券档位设计new】紧邻【促前券档位设计】

* **AND** 【促中预算紧张new】紧邻【促中预算紧张】

* **AND** 四条历史对话均可独立进入

#### Scenario: 对比同主题版本

* **WHEN** 用户在原版本与对应 `new` 版本之间切换

* **THEN** 两个版本各自保留消息、进度、产物和选中状态

* **AND** 新版交互不得改变原版本的 DOM、数据、状态、计时或应答策略

#### Scenario: 重新演示新版

* **WHEN** 用户在任一 `new` 会话点击“重新演示”

* **THEN** 只重置当前 `new` 会话

* **AND** 释放该会话生成的临时文件链接

* **AND** 原版本和另一条 `new` 会话保持不变

### Requirement: 可解释但不暴露内部思维链

系统 SHALL 展示任务理解、计划、当前步骤、使用证据、阶段结果和下一步，不逐字展示内部思维链、原始工具日志或临时推理草稿。

#### Scenario: 执行复杂分析

* **WHEN** Agent 开始执行一个已确认计划

* **THEN** 对话区显示当前步骤和可核验动作摘要

* **AND** 阶段完成后显示结论、证据、限制和下一步

* **AND** 不显示内部命令、隐式推理或无关日志

### Requirement: 计划与人工门禁

系统 SHALL 在复杂分析开始前提供计划确认，并只在关键决策和高风险动作前阻断。

#### Scenario: 信息足够

* **WHEN** 用户问题和上下文足以形成计划

* **THEN** Agent 直接展示计划卡

* **AND** 不额外提出不影响结果的问题

#### Scenario: 存在阻断信息

* **WHEN** 缺失信息会改变分析路径或最终决策

* **THEN** Agent 使用交互式问题卡请求用户选择

* **AND** 提供选项影响和自定义输入

### Requirement: 敏捷分析卡与策略结论板

系统 SHALL 使用对话内动态分析卡承接表格和图表，并使用右侧策略结论板收敛最终券策略，不要求过程分析映射为固定报告章节。

#### Scenario: 生成数据表格

* **WHEN** 当前步骤产出小规模比较表

* **THEN** 表格直接显示在对话内

* **AND** 长表在同一分析卡内展开

* **AND** 只有用户固定或结论引用的表格进入策略结论板

#### Scenario: 生成可视化

* **WHEN** 图表能够比文字或表格更清晰地解释趋势、对比、贡献、漏斗或规模

* **THEN** 对话内显示结论和主图

* **AND** 维度切换原位更新同一分析卡

* **AND** 图表支持展开、追问和固定为证据

#### Scenario: 更新策略结论

* **WHEN** 用户确认约束、固定证据或选择候选

* **THEN** 右侧策略结论板更新对应区块

* **AND** 不生成空章节或重复保存所有中间分析

#### Scenario: 导出产物

* **WHEN** 用户确认最终策略并主动选择导出

* **THEN** 系统根据当前策略快照生成文件

* **AND** 导出文件不反向控制对话和分析卡状态

### Requirement: 结果规模路由

系统 SHALL 根据数据规模和交互复杂度选择内联展示、下载文件或交互式分析面板。

#### Scenario: 返回小规模结果

* **WHEN** 结果不超过 6 个关键指标，或表格不超过 10 行且列数可控

* **THEN** 在对话内完整展示指标摘要或表格

* **AND** 提供追问和固定为证据操作

#### Scenario: 返回大规模结果

* **WHEN** 结果超过 10 行或需要复用

* **THEN** 对话内只展示核心结论、关键行和数据口径

* **AND** 提供 CSV 下载

* **AND** 结构化策略快照可额外提供 JSON 下载

#### Scenario: 返回交互式图表

* **WHEN** 图表需要筛选、联动、多维切换或悬浮提示

* **THEN** 对话内展示缩略图和“打开交互分析”

* **AND** 在工作台内打开可访问的交互式分析面板

* **AND** 不依赖外部网页或飞书文档接口

### Requirement: 最终回复结构

系统 SHALL 让两个 `new` 会话的最终回复依次包含核心结论、执行状态、数据口径、已生成产物和待补事项。

#### Scenario: 完成新版案例

* **WHEN** Agent 输出最终回复

* **THEN** 首屏先展示券策略核心结论

* **AND** 明确当前为已完成、待确认或待审批

* **AND** 列出数据时间范围、比较对象、关键假设和缺数边界

* **AND** 列出可用的表格文件、图表或交互分析入口

* **AND** 列出仍待补充的数据、业务确认和风险

### Requirement: 新版历史对话演示可见且可接管

系统 SHALL 允许两条 `new` 历史对话自动演示完整链路，同时保持每个用户确认可见并允许手动接管。

#### Scenario: 打开新版历史对话

* **WHEN** 用户点击【促前券档位设计new】或【促中预算紧张new】

* **THEN** 主区域进入对应新版工作台

* **AND** 首次进入时显示原问题、任务理解、数据状态和分析计划

* **AND** Agent 从目标确认问题和分析计划开始展示流程

#### Scenario: 手动接管

* **WHEN** 用户暂停演示、点击追问或输入自定义内容

* **THEN** 自动演示停止推进

* **AND** 当前对话、分析卡和结论板状态保持不变

* **AND** 用户可继续手动完成剩余步骤

### Requirement: 促前券档位设计new 七步协作脚本

系统 SHALL 在【促前券档位设计new】中按目标约束、大盘水位、类目机会、领取核销、实验竞对、候选方案、预算治理的顺序展示 7 步促前案例。

#### Scenario: 完成促前案例

* **WHEN** 用户完成全部门禁

* **THEN** 对话按 7 步完成，策略结论板同步收敛

* **AND** 最终生成策略快照、配置摘要、关键证据、波次预算、风险清单和待审批策略包

* **AND** 不改变现有 03/04 章节编号

### Requirement: 促中预算紧张new 六步协作脚本

系统 SHALL 在【促中预算紧张new】中按规则口径、总体对比、人群下钻、效率与规模拆分、预算候选、风险确认的顺序展示 6 步促中案例。

#### Scenario: 完成促中案例

* **WHEN** 用户完成全部门禁

* **THEN** 对话按 6 步完成，策略结论板同步收敛

* **AND** 最终建议保持“算法覆盖为主、jp/t8 可设保底”的条件式结论

* **AND** 最终状态为待审批灰度候选，不显示已执行

## MODIFIED Requirements

### Requirement: 双案例 Demo 表达方式

新增的【促前券档位设计new】【促中预算紧张new】 SHALL 使用“关键确认问题、执行轨迹、动态分析卡、策略结论板和最终策略快照”组成可见协作过程。原【促前券档位设计】【促中预算紧张】保持当前表达方式和既有数据结论不变。

## REMOVED Requirements

### Requirement: 将内部思维链作为实时执行内容

**Reason**: 内部思维链不适合作为产品可见内容，容易制造噪声、暴露无关中间推断并弱化可审计性。

**Migration**: 使用结构化执行轨迹替代，展示当前步骤、动作摘要、证据、阶段结果、限制和下一步。

### Requirement: 固定章节 HTML 报告作为过程主容器

**Reason**: 固定章节要求所有分析提前适配同一结构，状态同步成本高，也会把表格和图表从“支撑策略结论的过程”误变成主要交付目标。

**Migration**: 仅两个 `new` 版本使用动态分析卡承接过程证据，右侧只维护策略结论板；最终文件仅在用户确认结论并主动导出时按当前快照生成。两个原版本继续保留现有固定报告。

* 本轮不增加新的业务步骤，不改变促前 7 步和促中 6 步。
