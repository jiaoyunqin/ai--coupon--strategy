# 新建策略对话输入能力扩展 Spec

## Why

当前“新建策略对话”输入区只有附件占位按钮和 3 个 Luna 模型，无法在提问前选择技能、补充业务资源或快速复用具体问题。需要参考 iDA 的输入工具栏，在不引入后端依赖的前提下补齐技能、添加、模型和提问示例四类能力。

## What Changes

- 将输入区左侧的“添加附件”占位入口扩展为“添加”菜单，支持粘贴链接、接入已有资源和选择本地文件。
- 在输入区工具栏增加“技能”入口，支持搜索、查看详情、选择推荐技能，并区分不可取消的系统预置技能。
- 保留现有 Luna 模型并补充 6 个外部模型，继续通过单一模型选择器切换。
- 在空对话输入框下方、内置策略模板上方增加 3 条券策略提问示例，点击后只填入输入框。
- 为技能和添加结果增加紧凑上下文标签，并提供移除操作。
- 补充菜单互斥、焦点管理、键盘操作和窄屏折行规则。
- 不新增真实技能执行、文件上传、链接解析、资源请求或外部模型调用。

## Impact

- Affected specs:
  - 新建策略对话输入区
  - 技能选择与上下文标签
  - 添加链接、资源与本地文件
  - 模型选择
  - 空状态提问示例
- Affected code:
  - `index.html`
  - `newChatState`
  - `infrastructureData.skills`
  - `infrastructureData.knowledge`
  - `infrastructureData.datasources`
  - `renderNewChat`
  - `resetNewChat`
  - 新建对话输入区样式和事件委托
- Out of scope:
  - 真实技能安装、执行、权限申请或审计
  - 文件内容读取、上传和服务端存储
  - 链接抓取、资源鉴权和远程数据查询
  - 外部模型 API 调用、配额和费用展示
  - 用户自定义提问示例
  - 修改历史对话、促前案例或促中案例输入区

## Assumptions & Decisions

- 本轮只增强“新建策略对话”输入区，两个历史案例输入区保持现状。
- 所有新增能力均为本地交互演示；页面不得暗示已经完成真实技能调用、资源读取或文件上传。
- 输入工具栏顺序为：添加、技能、已选上下文标签、模型、清空、发送。
- 技能选择复用现有 `infrastructureData.skills`，通过展示元数据提供中文名称、推荐状态和是否系统预置，不复制第二份技能内容。
- 默认选中“预算归因分析”；“预算枚举查询”和“指标口径查询”为系统预置技能，始终选中且不可取消。
- 可选技能范围为“预算归因分析、预算异常检测、大促播报、舆情趋势洞察”；不在当前券策略场景直接展示 `markdown-to-html`。
- “添加新技能”跳转到现有技能管理视图，不在输入区内实现技能创建。
- 链接、已有资源和本地文件只形成当前对话的本地上下文标签；标签可移除，`resetNewChat()` 清空这些标签。
- 技能选择在当前新建对话内保留，`resetNewChat()` 恢复默认技能集合。
- 模型选择延续当前页面会话内保留的行为，不因模板筛选、提问示例或新建对话重置而变化。
- 提问示例只在无消息空状态展示；发送首条消息后由现有动态推荐问题接管，不重复展示。

1. `基于当前活动目标、预算和历史表现，给我三套促前券策略并说明取舍。`

## ADDED Requirements

### Requirement: 输入工具栏能力分层

系统 SHALL 在新建策略对话输入框内提供“添加、技能、上下文标签、模型、清空、发送”六类能力，并保持主输入区为视觉和键盘操作核心。

#### Scenario: 首次进入新建策略对话

- **WHEN** 用户首次进入或重置新建策略对话
- **THEN** 输入工具栏按既定顺序展示
- **AND** “预算归因分析”处于默认选中状态
- **AND** 模型默认为 `GPT-5.6-Luna Max`
- **AND** 链接、资源和本地文件标签为空
- **AND** 输入框自动获得焦点

#### Scenario: 对话正在响应

- **WHEN** `newChatState.isResponding` 为 `true`
- **THEN** 添加、技能、模型、清空和发送操作均不可修改当前状态
- **AND** 已选上下文标签保持可见
- **AND** 响应完成后恢复可操作状态

### Requirement: 技能选择菜单

系统 SHALL 提供与输入框关联的技能菜单，展示搜索、技能列表、状态标签和当前技能详情。

#### Scenario: 打开技能菜单

- **WHEN** 用户点击“技能”
- **THEN** 菜单展示搜索框和 Skill Catalog 中的 6 个技能
- **AND** 菜单首先展示“当前场景建议使用以下技能”的简短提示
- **AND** 当前选中、系统预置和未选中状态清晰可辨
- **AND** 默认详情区域展示当前聚焦或选中的技能名称、类型、标签和说明

#### Scenario: 搜索技能

- **WHEN** 用户输入技能名称、说明或标签关键词
- **THEN** 列表只保留匹配项
- **AND** 不修改任何技能的选中状态
- **AND** 无结果时展示明确空状态

#### Scenario: 选择可选技能

- **WHEN** 用户选择或取消可选技能
- **THEN** `newChatState` 同步更新已选技能 ID
- **AND** 已选可选技能在工具栏显示紧凑标签
- **AND** 点击标签的移除操作与在菜单中取消产生相同结果
- **AND** 操作不发送消息、不修改输入文字

#### Scenario: 操作系统预置技能

- **WHEN** 用户聚焦或点击“预算枚举查询”或“指标口径查询”
- **THEN** 技能详情可查看
- **AND** 选中控件保持禁用
- **AND** 页面明确标记“系统预置，不可取消”

#### Scenario: 添加新技能

- **WHEN** 用户点击技能菜单底部的“添加新技能”
- **THEN** 关闭技能菜单
- **AND** 打开现有技能管理视图
- **AND** 不创建重复的技能管理页面或本地伪技能

### Requirement: 添加上下文菜单

系统 SHALL 在“添加”入口提供“粘贴链接、接入资源、上传本地文件”三个选项。

#### Scenario: 粘贴有效链接

- **WHEN** 用户选择“粘贴链接”并提交 `http://` 或 `https://` 链接
- **THEN** 页面创建一个链接上下文标签
- **AND** 标签使用可读主机名或截断后的链接作为名称
- **AND** 原始链接只保存在当前页面状态中
- **AND** 页面不发起抓取或解析请求

#### Scenario: 提交无效链接

- **WHEN** 用户提交空值或非 `http://`、`https://` 链接
- **THEN** 页面展示就地校验提示
- **AND** 不创建上下文标签
- **AND** 焦点保留在链接输入控件

#### Scenario: 接入已有资源

- **WHEN** 用户选择“接入资源”
- **THEN** 页面展示 `infrastructureData.knowledge` 和 `infrastructureData.datasources` 中已启用的资源
- **AND** 用户可按名称筛选并选择资源
- **AND** 已选择资源形成带资源类型的上下文标签
- **AND** 相同资源不可重复添加

#### Scenario: 选择本地文件

- **WHEN** 用户选择“上传本地文件”并从系统文件选择器选中文件
- **THEN** 页面只记录文件名、大小和类型并创建本地文件标签
- **AND** 页面不读取文件正文、不上传文件
- **AND** 取消文件选择不改变当前状态

#### Scenario: 移除上下文

- **WHEN** 用户点击链接、资源或文件标签的移除操作
- **THEN** 对应项从当前新建对话状态和工具栏中移除
- **AND** 其他已选技能、上下文、模型和输入内容保持不变

### Requirement: 扩展模型选择

系统 SHALL 在现有模型选择器中按 Model Catalog 提供 9 个模型，并保持单选行为。

#### Scenario: 浏览模型

- **WHEN** 用户打开模型选择器
- **THEN** 模型按“券策略模型”和“外部模型”分组展示
- **AND** 当前模型具有明确选中状态
- **AND** 不展示使用率、费用、配额或“NEW”标签

#### Scenario: 切换模型

- **WHEN** 用户选择另一个模型
- **THEN** `newChatState.selectedModel` 更新为对应稳定 Value
- **AND** 工具栏立即显示新模型名称
- **AND** 页面用现有 Toast 提示切换结果
- **AND** 输入内容、技能和上下文标签保持不变

### Requirement: 输入框下方提问示例

系统 SHALL 在空对话的输入框下方、内置策略模板上方展示 Question Examples 中的 3 条问题。

#### Scenario: 浏览提问示例

- **WHEN** 新建策略对话没有消息
- **THEN** 3 条示例按固定顺序纵向展示
- **AND** 每条示例完整可读
- **AND** 示例与内置策略模板通过间距和分隔线形成清晰层级

#### Scenario: 使用提问示例

- **WHEN** 用户点击示例或通过键盘激活示例
- **THEN** 示例完整替换输入框当前内容
- **AND** 输入框自动调整高度并获得焦点
- **AND** 页面不自动发送、不新增消息
- **AND** 已选技能、上下文标签和模型保持不变

#### Scenario: 首条消息发送后

- **WHEN** `newChatState.messages` 不为空
- **THEN** 空状态提问示例和内置策略模板均不再展示
- **AND** 现有动态推荐问题继续显示在输入区上方

### Requirement: 菜单协调与状态恢复

系统 SHALL 保证技能菜单、添加菜单及其子面板同时最多打开一个，并在关闭后恢复合理焦点。

#### Scenario: 切换菜单

- **WHEN** 一个菜单已打开且用户打开另一个菜单
- **THEN** 原菜单先关闭
- **AND** 新菜单定位在对应触发按钮附近
- **AND** 输入文字和已选状态不变化

#### Scenario: 关闭菜单

- **WHEN** 用户按 `Escape`、点击菜单外部或完成单次添加操作
- **THEN** 当前菜单关闭
- **AND** 焦点返回触发按钮或下一步必要控件

#### Scenario: 重置新建对话

- **WHEN** `resetNewChat()` 执行
- **THEN** 所有菜单关闭
- **AND** 链接、资源和文件标签清空
- **AND** 技能恢复为默认集合
- **AND** 当前模型保持用户在本页面会话中的最后选择

### Requirement: 响应式与无障碍

新增工具栏、菜单、标签和提问示例 SHALL 复用当前视觉 Token，并支持桌面与窄屏键盘操作。

#### Scenario: 桌面布局

- **WHEN** 可用内容宽度大于 `760px`
- **THEN** 工具栏保持单行或紧凑换行
- **AND** 技能菜单以“列表 + 详情”结构展示
- **AND** 菜单不遮挡发送按钮和主要输入文字

#### Scenario: 窄屏布局

- **WHEN** 可用内容宽度不大于 `760px`
- **THEN** 上下文标签独立换行并可横向滚动或自然换行
- **AND** 技能详情改为当前条目内联展示
- **AND** 添加子面板和模型选择器不超出视口
- **AND** 页面和对话滚动区不产生横向溢出

#### Scenario: 键盘操作

- **WHEN** 用户只使用键盘
- **THEN** 可依次访问添加、技能、标签移除、模型、清空、发送和提问示例
- **AND** Enter/Space 可触发按钮和菜单项
- **AND** Escape 可关闭当前菜单
- **AND** 所有图标按钮具有中文可访问名称和清晰焦点轮廓

## MODIFIED Requirements

### Requirement: 新建策略对话空状态

新建策略对话无消息状态 SHALL 按“欢迎信息 → 三条阶段开场卡片 → 增强输入区 → 三条提问示例 → 内置策略模板”的顺序展示。增强输入区 SHALL 复用唯一的 `newChatComposer` 节点；模板筛选或提问示例操作不得重建输入控件或丢失当前状态。

#### Scenario: 空状态重绘

- **WHEN** 用户筛选模板、选择技能、添加上下文或切换模型
- **THEN** 页面继续使用同一个输入框、模型控件和发送按钮
- **AND** 当前输入文字、技能、上下文和模型状态保持一致
- **AND** DOM 中不存在重复输入区 ID

### Requirement: 新建策略对话提交行为

提交问题 SHALL 继续只以输入文字创建用户消息；技能、上下文和模型作为当前对话的本地配置状态保留，不拼接到可见消息正文，也不宣称已完成真实外部调用。

#### Scenario: 带配置发送问题

- **WHEN** 用户已选择技能、添加上下文并发送非空问题
- **THEN** 用户消息正文只展示输入文字
- **AND** 现有思考进度和模拟回复流程正常执行
- **AND** 页面不产生真实网络调用
- **AND** 已选配置在响应期间保持可见但不可编辑

## REMOVED Requirements

无。
