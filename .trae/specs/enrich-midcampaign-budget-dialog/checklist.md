# 验收清单

## 导航与默认状态

- [ ] 点击左侧“促中预算紧张”会进入独立案例会话，而不是只显示 Toast。
- [ ] 左侧历史项选中状态与当前主视图一致。
- [ ] 会话顶部显示案例标题、决策问题、V1/V15、案例状态和步骤进度。
- [ ] 首次进入只展开问题重述、数据状态和分析计划，没有直接展示最终结论。
- [ ] “回到工作台”可恢复原促中调优工作台，且原有交互仍可用。

## 案例问题与分析计划

- [ ] 决策问题准确表述为预算紧张下应优先覆盖大盘 L4-L5 还是 jp/t8 重点人群。
- [ ] V1 准确展示为“90% L4-L5 保证有 X，剩余人群算法选择 40%”。
- [ ] V15 准确展示为“jp/t8 必发，不区分 L 等级，剩余人群算法选择 40%”。
- [ ] 页面明确说明 V15 用优质 jp/t8 中的 L1-L3 置换部分大盘 L4-L5。
- [ ] 六步分析计划顺序与规格一致，并区分待执行、执行中、已完成。
- [ ] 用户可确认分析计划，确认后分析内容按步骤展开。
- [ ] 用户可补充预算敏感性、L4/L5 细分、jp/t8 量级和上线风险分析。
- [ ] 自定义补充要求会显示在计划中，并在后续分析中被引用。

## 数据准确性

- [ ] 总体数据准确展示 V1/V15 人均支付 GMV 39.67% / 36.88%。
- [ ] 总体数据准确展示 V1/V15 人均补贴 ¥1.29 / ¥1.22。
- [ ] 总体数据准确展示 V1/V15 增量 GMV 兑换比 6.32 / 6.24。
- [ ] 总体数据准确展示 V1/V15 支付费率 4.51% / 4.33%。
- [ ] 重点人群数据准确展示支付 GMV 57.74% / 66.83%、补贴 ¥5.50 / ¥6.25、兑换比 5.91 / 6.01。
- [ ] L4 数据准确展示支付 GMV 43.47% / 38.36%、补贴 ¥3.30 / ¥2.79、兑换比 6.02 / 6.29。
- [ ] L5 数据准确展示支付 GMV 42.49% / 38.93%、补贴 ¥8.66 / ¥8.18、兑换比 6.08 / 5.90。
- [ ] 页面准确展示 jp/t8 约 6,400 万、大盘 L4-L5 约 8,000 万及约 20% 规模差。
- [ ] 数据项区分“已提供”“案例推导”“待用户输入”，没有伪造线上实时状态。
- [ ] 未提供精确预算、X 单人成本时，页面不会显示虚构的绝对金额或覆盖人数。

## AI 分析质量

- [ ] 总体 AI 小结同时包含结论、指标依据、限制和下一步。
- [ ] AI 明确将 6.32 与 6.24 解读为基本持平，不夸大 0.08 的差异。
- [ ] AI 明确说明 L4 6.02、L5 6.08、jp/t8 6.01 接近，不能证明 jp/t8 显著更高效。
- [ ] AI 明确区分总体均值、人群结构、兑换效率和可覆盖规模。
- [ ] AI 将 V15 总体增量偏低解释为 jp/t8 人群池较小带来的量级效应。
- [ ] 页面没有出现“因为 jp/t8 更小，所以大盘增量更少”这类方向错误的表述。
- [ ] AI 不会仅根据重点人群支付 GMV 较高就宣判 V15 整体最优。
- [ ] 最终结论说明当前数据无法无条件证明 V1 或 V15 胜出。
- [ ] 最终推荐为“大盘 L1-L5 中由算法选择部分人群覆盖”，并给出适用条件。
- [ ] 备选策略包含“jp/t8 保底 + 剩余预算算法分配”。

## 预算决策与风险

- [ ] 未输入预算时展示参数化决策规则，并明确等待业务补充。
- [ ] 用户输入预算可覆盖人数或比例后，系统会基于 6,400 万和 8,000 万更新覆盖缺口。
- [ ] 候选策略比较至少包含覆盖规模、预期效率、主要风险和适用条件。
- [ ] 风险清单包含统计显著性、样本稳定性、人群结构差异、预算缺失和算法挤占风险。
- [ ] 上线监控项包含预算流速、券流速、领券 UV、核销 UV、核销率、客单和增量兑换比。
- [ ] 风险项可追问并可标记为已确认。
- [ ] 最终候选保持在人工确认门禁后，确认前不显示已执行状态。
- [ ] 二次确认后只记录“待审批/灰度候选”，不触发真实发券、预算或人群配置。

## 追问与补充分支

- [ ] 总体对比卡、人群行、规模卡、风险项和 AI 小结均有可发现的追问入口。
- [ ] 追问面板显示当前上下文摘要，预设问题随目标类型变化。
- [ ] 可追问“为什么 V15 总体增量低但兑换比持平”。
- [ ] 可追问“L4、L5 和 jp/t8 的兑换比是否真的没有差异”。
- [ ] 可追问“6,400 万与 8,000 万如何影响增量”。
- [ ] 可追问“预算再缩减 10% 时如何调整覆盖”。
- [ ] 可追问“为什么最终不直接选择 V1 或 V15”。
- [ ] 可追问“上线后需要监控哪些止损指标”。
- [ ] 用户可提交自定义问题。
- [ ] 追问提交后依次展示理解问题、定位数据、完成归因、输出结论，不直接瞬间给答案。
- [ ] 追问回答引用当前案例数据和当前分析步骤。
- [ ] “定位到数据”会滚动并高亮对应模块。
- [ ] “加入分析计划”会把追问要求写入分析步骤。
- [ ] “生成候选方案”会进入预算候选比较或最终决策阶段。
